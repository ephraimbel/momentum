The integrated patch removes eager label rasterization, creates the label/formatter lazily, and renders labels only during visible layout. Only the scale-bar implementation differs from upstream runtime sources; the shared Xcode package checkout was not patched.

Maintenance details: `Vendor/MapboxMaps/MOMENTUM-PATCH.md`. Exact patch: `docs/patches/mapbox-11.25.0-lazy-scale-label.patch`.

Tests cover zero rendering calls during construction/configuration and hidden layout, visible labels, cache reuse, reveal-after-hide, unit/locale invalidation, and every upstream metric/imperial/nautical bar-count fixture.

## Startup hardening — MOMENTUM-IOS-H

[Issue](https://momentum-l6.sentry.io/issues/7722451461/), **1.7.5 (43)**, iPhone 12 Pro Max / iOS 26.6.1: a 2.6–3.4 second non-fully-blocked hang shortly after launch. Rechecking the issue still showed one event. The sampled stack contains the normal event loop and application entry; the MetricKit breadcrumb is an aggregate, not proof of the work responsible for this particular hang.

`DeferredLaunchWork` replaces the single main-thread startup burst. It waits for first paint, suspends between steps, stops on cancellation/inactivity, and resumes unfinished steps when active. A newer invocation supersedes an older suspended invocation, and completed work does not repeat. SDK calls stay on the main actor where required.

Sentry gets only finite startup-phase names and started/completed states. Tracing, replay, screenshots, identity and content capture remain disabled. These breadcrumbs improve the evidence available if a later launch hangs; they do not prove that this existing event was caused by the deferred work.

Late orphan cleanup also excludes Live Activities created by this process, so a workout or rest timer started between startup steps cannot be ended as an orphan. The ownership decision and interleaved startup scenario have a regression fixture.
