## Changes

- **[MOMENTUM-IOS-R](https://momentum-l6.sentry.io/issues/7729256000/), 1.8.5 (46): fixed source path.** The breadcrumb immediately before the fatal `PlannedSession.discipline` read records session removal. `PlanView.restLine → neighborKind` then evaluated a retained board map containing the deleted object. Invalidate the map before saving a removal, filter detached/deleted rows, and check lifecycle metadata again inside deferred SwiftUI row/drag closures and the neighbor reader. Regression reads a retained session both before and after deletion is saved.
- **[MOMENTUM-IOS-P](https://momentum-l6.sentry.io/issues/7728942228/), 1.8.5 (46): fixed source path.** `WorkoutSnapshotHealer.sweep` filtered retained workouts after previous repairs had suspended. The sweep now carries UUID queues; repair captures scalar input, fetches existing detail rows instead of using `model(for:)` faults, and re-fetches after rendering. Deletion, detail replacement, a changed style, a newer image and cancellation discard stale results. Tests delete the workout or replace its detail inside the injected renderer, verify a newer image wins, and verify normal repair persists exactly once.
- **[MOMENTUM-IOS-T](https://momentum-l6.sentry.io/issues/7729473078/), 1.8.5 (46): repeated-fetch path removed.** The watchdog stack goes through notification filtering into `AdaptivePlanRecord.fetch`. `AdaptivePlanService.Disclosure` resolves the calendar and review visibility once into values before each session/race scan. Individual detail callers use the same rule. This removes per-session sidecar fetches and repeated review JSON decoding; it does not prove every watchdog report shares this cause.
- **[MOMENTUM-IOS-K](https://momentum-l6.sentry.io/issues/7726501397/), 1.8.0 (44): encoding workload reduced.** Sync previously encoded every bundled exercise on every save. Snapshots now include exercises referenced by the current plan, all saved plan snapshots, and included workout evidence, plus every custom exercise. Recovery-feedback membership also uses a Set rather than a nested scan. A 500-unused-exercise fixture verifies active, archived and custom references survive, and the existing hybrid restore/idempotency tests pass. JSON encoding remains synchronous; this is a workload reduction, not a guarantee against hangs for arbitrarily large custom catalogs.
- **[MOMENTUM-IOS-Q](https://momentum-l6.sentry.io/issues/7729082868/), 1.8.5 (46): camera work bounded for ordinary routes.** The hang sampled Mapbox's overview coordinate bridge. The zero-pitch, north-up overview now fits first/last points and latitude/longitude extrema (at most six), while drawing the original complete route. Dateline-spanning routes retain the full input to preserve Mapbox wrap selection. Tests preserve exact extrema for 100,000 points and handle invalid/empty input. This does not eliminate SDK initialization or rendering stalls.
- **[MOMENTUM-IOS-S](https://momentum-l6.sentry.io/issues/7729335043/), 1.8.5 (46): diagnostics improved, cause unknown.** The annual purchase failure has placement/product tags but no error code. Future failures include a numeric code and a fixed stage (`sdk_unavailable`, `product_unavailable`, `entitlement_pending`, `revenuecat`, `store_error`). Free-form errors, receipts and account data are not sent. Ordinary cancellation stays silent. The existing event cannot establish whether the store, billing configuration or entitlement processing failed.
